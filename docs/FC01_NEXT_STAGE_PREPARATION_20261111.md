# FC01 下一阶段需要准备什么

这里的“已有”区分用户此前描述、仓库里确实存在的内容和本轮实际检测。此主机没有连接香橙派、FC01 或相机；不据此判断设备已经接好、已正确供电或完成标定。

## 硬件与安装资料

| 项目 | 用途与必要性 | 当前证据、提供方 | 缺失影响 |
| --- | --- | --- | --- |
| FC01、实际 PX4 固件、遥控器 | 真实状态、RC/Kill/接管；拆桨验收必需 | 用户此前描述已有；用户提供固件版本/构建标识、参数导出、遥控档位映射 | 无法证明消息版本、RC 和失联行为与源码一致 |
| Orange Pi、系统镜像、供电与存储 | ARM64 部署和性能测量必需 | 用户此前有测试；需用户提供型号/内存、系统、内核、ROS 版本及实际部署报告 | x86 构建不能证明 ARM64 性能或稳定性 |
| USB 全局快门相机 | VIO/SLAM 图像输入；采用该路线时必需 | 产品链接只说明宣传定位；用户/视觉同学提供实物型号、传感器、镜头与 USB 描述 | 不能确认真实分辨率/帧率组合、曝光、驱动或时间戳 |
| 相机固定件与外参 | 确定 optical/传感器坐标到机体 FRD 的旋转、杆臂，必需 | 用户提供实际安装图/尺寸，视觉同学提供标定结果与方法 | 方向错误、杆臂速度修正错误；不能从相机朝向猜值 |
| MTF-02P 与接口线 | 下视光流和近地测距；是否必需取决于估计方案 | 用户曾提供厂商页面，未证明已接好；用户确认型号、固件、协议跳线、接口定义 | 无法验测距/流质量和 PX4 是否融合 |
| 5 V 供电、共地和匹配电平的串口线 | 仅在 MTF-02P 实际接入时必需 | 厂商标注 5 V 供电、UART 115200、LVTTL；接线前由用户核对 FC01 空闲端口针脚/电平 | 接错口或与 Agent 共用串口会使链路方案无效 |
| IMU 来源与安装信息 | 若采用 VIO，需要同步惯性数据和相机-IMU 标定 | 视觉同学说明使用 PX4 IMU 还是独立 IMU；用户提供实际安装 | 不能假设单目里程计自动具有米制尺度和稳定速度 |
| 标定板、已知距离/尺度参考与纹理地面 | 相机内参、尺度、测距/光流验证；按所选算法准备 | 视觉同学给出标定方法和图案规格，用户准备场地 | 无法定量验证误差；不建议购买没有对应算法用途的设备 |

MTF-02P 是**光流与测距模块**，不能当作已经提供原始 USB 图像的 SLAM 相机。厂商当前页面给出 UART 115200、Micolink/Mavlink/MSP、50 Hz、5 V，以及受反射率和光照条件限制的测距范围；这些是规格，不能当成当前机体的实测精度。

若目标是先改善 PX4 自身高度/水平估计，优先核对“模块 → FC01 独立空闲串口 → PX4 驱动/EKF → 现有 vehicle_local_position”方案，可保持 FC01 控制接口不变。先确认实际端口和协议、安装朝向、原始 range/flow/quality、EKF 是否真正融合，再决定是否调整参数。厂商针对 PX4 1.14–1.16 的说明使用 MAVLink 串口及 `EKF2_OF_CTRL`/`EKF2_RNG_CTRL` 等；本轮没有替你修改这些参数，也不建议照抄高度参考设置。

如果视觉算法必须直接消费模块数据，则由视觉侧另行提供驱动、消息、测量时钟和标定，再形成实际状态；不能把原始光流值直接当作世界系 m/s。无需为了已有 FC01 接口重复占用 Agent 的串口或另创冲突消息包。

规格来源：[MicoAir MTF-02P 官方页面](https://micoair.com/optical_range_sensor_mtf-02p/)。本轮抓取原文和 SHA 在验证归档中。相机淘宝型号未经过实物核验，不能据宣传的“120 帧”认定完整分辨率、曝光和算法负载下都能达到该值。

## 软件与视觉同学的交付

| 需要提供 | 用途/是否必需 | 当前与负责人 | 缺失影响 |
| --- | --- | --- | --- |
| 可复现的视觉源码或安装制品、依赖、启动参数、版本 | 调试与长期维护必需；至少要有可固定版本的可运行制品 | 视觉同学；本仓库无 VIO/SLAM 本体 | 无法重现算法崩溃、时间和质量问题 |
| ROS 2 Humble/ARM64 支持说明和算力实测 | Orange Pi 部署必需 | 视觉同学提供目标机 CPU/RAM/温度/帧率 | 不能以桌面性能承诺香橙派可用 |
| 实际状态 Topic 与完整消息类型 | 视觉状态接入必需：标准 `nav_msgs/msg/Odometry` | 原始 topic 尚需双方确认；视觉同学给定 | 适配器不能自动猜测 vendor topic |
| 配对 `jikl_fc01_system/msg/VisionHealth` | 当前合同必需，stamp 与对应 Odometry 完全相同 | 消息已在本包生成；视觉同学实现真实语义 | 只有 Odometry 不足以声明尺度/时间/跟踪有效 |
| `jikl_fc01_system/msg/VelocityCommand` 与 `/fc01/vision/velocity_command` | 上层目标速度接口；本阶段只诊断 | 接口已实现；视觉制导方按同一包编译 | 类型同名但包不同不视为兼容；不接管飞行控制 |
| 世界/机体/optical 坐标、单位、四元数顺序、twist 所在帧 | 实际状态转换必需 | 视觉同学提供文字合同和可验证示例 | 不能从 frame_id 名字猜旋转，也不能把目标速度当反馈 |
| reset、重定位、tracking/quality、失效与重启语义 | 控制前必需 | 视觉同学说明序号/会话/时间如何处理 | 旧缓存、旧地图或旧目标可能被错误解释 |
| 共享接口与工作区安排 | 同一类型身份必需；另建工作区可选 | 复用当前 `jikl_fc01_system`，先构建/source；可用独立视觉 overlay | 不需要为单个 .msg 另建冲突包；不能仅复制文本就算兼容 |

USB 相机至少需要：实际图像尺寸与像素格式、可持续帧率、曝光时间/自动曝光控制、读出方式、镜头/FOV、内参与畸变、图像时间戳代表曝光开始/中点/完成的哪一个时刻、硬件或软件同步方式、驱动版本、USB 带宽和丢帧统计。若没有同步 IMU 和真实尺度方案，应先明确它是 VO 还是 VIO，不能承诺完整稳态定位。

## 最小真实记录集合

请一次任务保留同一时间段的材料；发生故障前后都要覆盖，不能只截最后一条原因。

| 数据 | 作用和必要性 | 负责人/当前状态 | 缺失后无法回答 |
| --- | --- | --- | --- |
| 原始 Odometry、VisionHealth、目标速度 rosbag2 | 验证真实频率、时间、质量、reset 和状态/目标隔离；接视觉前必需 | 视觉同学录制；当前仓库回归为合成数据 | 算法是否输出可信实际状态 |
| 图像/CameraInfo、IMU、标定文件与外参版本 | 追溯估计误差、尺度与相机-IMU 同步；VIO 调试必需 | 视觉同学与用户按所选算法提供 | 漂移究竟来自标定、纹理、同步还是估计器 |
| MTF 原始距离、光流、质量及设备时间 | 选择该模块时必需 | 用户/视觉方录制，并标注地面/光照/高度 | 规格是否满足实际反射率、纹理和运动速度 |
| PX4 ULog 与完整参数、固件标识 | 高度、推力、模式切换、FailSafe 和发布异常验证必需 | 用户从对应飞控任务导出 | PX4 实际是否接收/采用命令及为什么退出 |
| 当前版本导航 report ZIP、控制器日志和部署身份 | 对齐运行源、反馈过期和恢复阻塞；每次测试建议提供 | 工程已有报告命令；用户运行当前源码版本 | 测试的究竟是哪版代码/参数、何时拒绝 |
| 主机性能与 DDS 指标 | ARM64 性能与带宽验收必需 | 用户录制 CPU/RAM、温度/降频、USB丢帧、topic频率/带宽和发布间隔 | CONTROL_LOOP_STALL 是否由调度/负载/链路造成 |
| 实际场景说明 | 区分拆桨、固定台架、自由飞行和人工接管时刻，必需 | 用户记录，说明负载、电池、桨/电机和地面 | 不能把台架爬升超时当成飞行动力不足，反之亦然 |

本轮没有自动向他人索取数据或发送消息。你可将这份合同同步给视觉同学，由双方提供真实版本、话题和记录。

## 尚不能确认的因素

高表示进入真实视觉闭环前必须补证；中表示影响后续方案或表现。它们不阻止继续离线开发，但会阻止对应功能的飞行验收。

| 未决项 | 当前证据及不能成立的结论 | 如何确认 | 优先级/阶段影响 |
| --- | --- | --- | --- |
| VIO 真实尺度 | Health 有声明位，没有实际视觉数据；不能认定米制尺度成立 | 已知距离轨迹、静止/运动 bag、与独立参考比较 | 高；阻碍视觉闭环验收 |
| 单目速度 | 有相机产品信息，没有算法/IMU合同；不能认定稳定速度已实现 | 明确 VO/VIO、尺度来源，检查静止噪声/动态延迟 | 高；阻碍水平闭环 |
| MTF 测距 | 只有厂商条件规格，无本机数据 | 多高度/表面/光照实测，保留无效/饱和标记 | 高；阻碍依赖它的定高验收 |
| 光流纹理适应 | 无本机 flow/quality 记录 | 低纹理、反光、暗光和倾斜运动测试 | 高；阻碍光流导航验收 |
| 实际消息频率 | ROS smoke 是合成来源，不是相机吞吐 | 目标机 bag、hz、延迟与丢包分布 | 高；决定 TTL 与闭环预算 |
| 与 PX4 的时钟对应 | 代码能拒绝不可信时间，没有实测偏移/漂移 | 同程 source/receive 时间及 PX4 ULog，对齐误差区间 | 高；阻碍可信控制反馈 |
| 坐标与安装 | 数学转换有验证，实物外参未知 | 标定、已知方向/角速度/位移样例验证 | 高；方向错误会直接影响控制 |
| Orange Pi 算力 | x86 测试通过不是 ARM64 负载证明 | 相机+估计+Agent+控制共同负载与温度记录 | 高；阻碍目标机系统验收 |
| DDS/串口带宽 | 来源与队列门存在，没有真实拥塞数据 | burst/断连恢复压力下测丢包、source age、CPU | 高；阻碍链路可靠性验收 |
| 估计误差/延迟 | 未提供真实轨迹；不能只凭质量标量认定精度 | 独立参考、静止漂移、动态延迟/重定位 bag | 高；决定控制参数和速度限幅 |
| 过去推力不足 | 保留原候选值；本轮无对应真实动力记录 | 同程 ULog/电池/输出/高度、实际机重和动力资料 | 高；阻碍继续动力试验的结论 |
| 过去垂速异常 | 监测已改为诊断；根因不能从本轮合成测试得出 | 同程 z、vz、z_deriv、reset、采样时间和估计器日志 | 高；阻碍传感器一致性验收 |
| 地面参考可靠性 | 地面/新样本/reset 有软件回归，真实基准仍需验 | 多次落地上锁、静置、重建与独立高度记录 | 高；阻碍连续飞行验收 |
| 异常发布后 PX4 响应 | 本地 sink 的成功/拒绝有模拟；没有本轮 PX4 执行记录 | 拆桨下核对模式/接管/失联与参数及 ULog，随后评估动力条件 | 高；阻碍真实异常处置验收 |

## 试验顺序与下一步开发

1. **Ubuntu x86_64**：继续纯计算、异常消息、原/新差分、消息生成、安装和隔离 ROS 收发。这些本轮已实际执行对应项目；不运行生产飞控节点。
2. **Orange Pi 离线**：用当前源码清单构建，核对实际安装模块/消息库/二进制与构建证据，确认旧 `dist` 包没有被误当成本轮版本。测试可以先不连接 FC01。
3. **真实 PX4 拆桨**：核对版本、参数、消息兼容、RC/Kill/接管、Agent 断连恢复、状态新鲜度与地面恢复；收集同步 ULog/report。此阶段仍不启用视觉控制。
4. **真实视觉静止与手持记录**：确认尺度、坐标、时间、质量、reset、外参及目标机性能预算，再决定 TTL、速度和质量门槛。开发不要用猜测值替代这些结果。
5. **后续代码工作**：基于真实合同接通已校验实际状态与目标速度仲裁；补足需要的协方差变换、明确传感器接入与失效策略；检查视觉消息资源预算和必要的异步 CSV。这些工作仍可先离线完成。
6. **受控动力试验**：只有前序真实数据、动力余量、调度、接管/失联和高度参考问题得到验证后再另行制定。本轮工程审查没有自动授权或执行它。
