# 视觉接入：边界问题修复与阅读说明

本轮继续审查速度诊断、实际状态校验和离线预览。下面的问题均先独立复现，再修改对应准备模块。原自动起飞、Runtime、RC/Kill/Failsafe、恢复和最终飞控发布路径保持原代码。

## 修复了什么

| 问题 | 修改前的实际表现 | 修改后的行为 |
| --- | --- | --- |
| 速度诊断时钟回退 | 单调时间从 10 回到 9.9，下一帧 9.91 就能重新接受，尚未追上原时间；ROS 时间也有同样问题 | 保留最大已观察时刻；回退期间拒绝候选，追上后允许正常新帧恢复。被拒绝的序号不推进可信记录 |
| 事件对象共用嵌套数据 | 调用方修改 `receive()` 或 `drain_events()` 返回值，可以清空内部异常原因；待写日志也可能受影响 | 返回事件和待写异常各自保存独立副本，外部整理结果不再污染保留证据 |
| 外参配置内部仍可修改 | `frozen` 配置中传入的平移列表被外部改动后，同一估计周期的位置能静默变化 100 m | 构造状态校验配置时，将四组旋转/平移保存为独立数值元组；此后原列表的修改不改变转换 |
| 姿态小角度比较失真 | 极小正门限下，舍入误差会将完全相同姿态算成约 `3e-8 rad` 的变化，也可能把真实微小转角算成零 | 状态校验和 C++ 预览使用符号对齐后的差/和范数与 `atan2`；相同姿态和等价反号姿态为零，真实微小转角仍按门限检查 |
| 纯 Python 数值校验抛异常 | `10**400` 进入配置、接收时钟或速度的有限数检查时抛出 `OverflowError` | 配置/时钟给出明确 `ValueError`，非法速度按原错误原因拒绝，后续正常数据仍能接收 |

最后一项属于纯 Python API 的边界健壮性；生成的 ROS `float64` 字段不能携带这种任意精度整数。

## 从哪里读

- `native/tools/velocity_command_diagnostic.py`：先看 `_observe_clocks()`，再看 `_event()`、`drain_events()` 和 `DiagnosticWriter.record()`。中文注释说明保留时间基准、复制异常证据的目的。
- `native/tools/vision_state_validation.py`：`ValidationConfig.__post_init__()` 固定配置副本；`_attitude_step_rad()` 计算姿态变化；`_continuity_errors()` 使用显式门限。
- `native/src/jikl_fc01_system/include/jikl_fc01_system/velocity_command_input.hpp`：`Session.state()` 的姿态连续性段采用相同几何公式，保留原拒绝原因和离线会话重建机制。

姿态比较先把四元数符号对齐，因为 `q` 和 `-q` 表示同一旋转。对于单位四元数，差向量和和向量的长度分别对应夹角四分之一的正弦、余弦，因此：

```text
姿态变化角 = 4 × atan2(差向量长度, 和向量长度)
```

这不需要额外放宽门限。回归同时检查完全相同姿态、整体反号、门限两侧的小转角，以及应当拒绝的明显跳变。

配置检查的多条件判断、字段列表和错误说明按步骤展开；保留短中文注释，说明每步为什么存在。完整入口与实际状态/目标速度的区别见 [代码阅读说明](VISION_CODE_READING_GUIDE_20261111.md)。该说明里的差分数量对应上一轮纯重构，本轮有意修复上述边界行为，以新的回归和复现结果为准。
