## 独立审查后的校正

不同作者互审 Node、Runtime、Core 与 11 份控制头。发现并修正的是讲解准确性问题，而非控制逻辑：

1. 命令发送后重取的是缓存水位，此时未必收到新 PX4 样本，不能写成物理结果已取证。
2. `if (const auto cause = ...)` 是条件中的局部声明，不能混同 `if (init; condition)` 语法。
3. `mode.accepted` 是 Runtime 审核后的摘要，还包含176偏斜候选与独立新状态的窄路径。
4. 控制器调用“可能”推进积分/slew；输入早退不完成闭环推进，失败不会自动回滚已写状态。
5. 上锁请求一旦真正提交便不可撤回；进入请求阶段本身仍不证明已提交。
6. `rc_source_selected/rc_sticks_moving` 会参与准入与接管，不能一概写成只用于诊断。
7. `source_host_stamp` 的赋值不证明同步有效，仍须看 `valid/validated`。
8. 离散队列也保留恢复边沿，不能只称“负面观测”。
9. 176示例的100ms边界按原 `<=` 严格拒绝，说明改为“触及或越过下界”。

具体审查记录及各作者的词法检查见证据包；最后集成检查覆盖上述注释校正后的最终源码。
