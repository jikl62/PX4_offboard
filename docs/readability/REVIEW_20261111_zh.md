## 原起飞链怎样读

`RcNavigationStart` 先积累新鲜、有效、未解锁、着地静止的反馈，并绑定姿态和垂向估计器 reset。满足地面窗口才允许零推力预发送。READY 不是解锁命令：人工 RC 开关的新边沿及飞控实际解锁反馈仍必须出现，导航档位与真实 Offboard 也各有证据门。

准入汇合到原姿态高度 Core 后，目标来自已经校验的 `rc_target_height`，当前生产候选为 **1.5 m**。Core 决定任务阶段和推力调度，`VerticalController` 只计算，不直接发布 ROS，也不自行授予控制权。

PX4 的 NED `z`、`vz` 向下为正，单位分别是 m、m/s。地面参考是 `z0`，所以向上相对高度为 `height=z0-z`，向上速度为 `speed=-vz`。高度误差乘 `height_gain`（1/s）得到向上速度目标，再叠加轨迹速度前馈并限制爬升/下降速度。速度误差乘 `velocity_gain`（s/m）得到归一化推力修正，积分增益单位 1/m；累计速度误差乘时间后再形成推力积分。

原推力计算仍是悬停基准、速度比例项和积分项。起飞调度给上限，物理包络给上下限，slew 再限制相邻周期的变化；积分的试算和接受顺序没有调换。受限时禁止继续积累受限方向误差，同时允许已有积分退回零。源码旁已解释为什么不能在计算之后简单补一个 clamp。

“任务开始”“本地动作提交”“离地证据成立”“目标高度稳定”“导航允许”分别记录。导数速度差 `vz-z_deriv` 仍是独立诊断；位置积分残差、测量有效性、时钟和原飞行包络保持各自原门槛。没有增加未经验证的独立速度差停机条件。

节点得到的只是控制计划。它在目标、心跳和动作真正提交前重新采样上下文，重新检查时钟、反馈、控制权和完整周期预算。任何部分提交异常仍锁存完整性故障。本地发布成功不证明 PX4 收到或采用；真实动力结果需要对应 ULog。

接管后不会自动夺回控制权。当前故障是否允许安全重新准备、开关是否复位、真实未解锁地面、新样本和静止窗口必须重新成立；同一轮中任何危险事件仍能否决恢复。不会因最后一帧恢复正常而忽略中间异常，也不会因重建任务清除进程级 ACK 歧义水位。

## 视觉与时间的边界

`Odometry` 是飞机实际状态；`VelocityCommand` 是上层希望达到的目标速度。两者不能互相替代。新速度类型继续复用 `jikl_fc01_system/msg/VelocityCommand`，话题是 `/fc01/vision/velocity_command`，当前只读诊断。既有视觉运动链仍使用 `VisionState + NavigationCommand`；本轮没有把新速度指令接到生产姿态/推力发布口。

`visual_navigation_enabled=false` 保持不变。源码已说明米制尺度、外参、杆臂、世界/机体坐标、Hamilton wxyz 与 ROS xyzw、质量、协方差、reset、同戳健康配对和失效撤销。未完成的协方差变换没有在注释里冒称完成。

本机 `steady` 秒只管周期和租约，ROS 纳秒换算到 PX4 接口使用的微秒只是换单位，不会建立与 PX4 的时钟同步。主机跳变检测与外部 Agent 同步前提、逐源域检查分别解释。收到新消息也不等于获得新测量：重复原始 sample 不会续鲜。

1. 文件覆盖：从实际 Git 管理/未忽略文件扫描候选，自研源码逐个登记；生成产物、历史反例、数据/文档、构建缓存分别排除并保留路径与原因。

3. 可读性：先审查格式样例，再统一展开 C++ 单行多语句和 Python 密集语句；不排序 include、不重写 C++ 字面量、不插入花括号、不改公开命名。额外独立复核列出仍保留的复杂函数。
4. 行为保真：注释阶段和排版阶段分别对不可变 Git 基线检查 C++ 完整 raw token、预处理逻辑行、Python 完整 AST、Shell 执行行/heredoc、YAML 类型/值、MSG 声明、CMake token 和 XML 语义，再做实际回归与构建。

`tests/readability_equivalence.py` 可重复执行。它识别字符串中的注释符，检查函数式宏邻接，遇到无法可靠解析的内容明确失败。它不会执行被检查脚本，也不把新增文件冒充已有等价验证。其正反例包括真实字面量改变、预处理边界、heredoc、参数类型和历史原字节保护。

仅排版阶段，全部原有 Python 的完整 AST 一致，没有“忽略 docstring 后相同”的放宽。后续离线映射解析与测试插桩兼容修复属于有意逻辑差异，单独列出、测试并提交；不能用排版阶段的通过结果冒充这些文件最终 AST 未变。

## 确认的问题与独立处理

格式化使旧离线参数映射正则和两处临时节点测试插桩失配。修复只让相同 C++ token 之间允许空白/换行，继续要求唯一插桩、原映射数量门和完整映射一致；真实成员改变仍可检出。没有修改生产 C++ 来迁就测试，也没有删除原飞行断言。

早先分批报告把 3,500 多个构建缓存的排除原因逐项重复，单个 JSON 超过安装器 1 MiB 载荷上限。最终扫描器将原因按类别共用，仍保留每个具体排除路径；发布包原 512 文件、8 MiB 总量、1 MiB 单项限制不变。不会为装下报告而放宽安装校验。

真实 Humble 视觉适配器在 SIGINT 与待取订阅回调交错时，可能从 rclpy `take_message` 抛 RuntimeError。相同条件下旧基线也能复现；字节/AST与对照记录保留。生产适配器未因本轮可读性工作改变停机行为。最小候选只在副本验证，补丁与适用范围见 `candidates/`，没有应用到部署源码。

## 保留的结构债与验证缺口

中文注释完成不等于所有复杂函数已经拆分。`Core::step`、`Runtime::step/request/ack`、`RcNavigationStart::step`、`SystemNode::tick/snapshot/state/observe_pending_safety` 等仍然较长；本轮展开布局、加入状态段落，保留原早返回、短路及事务顺序。完整的函数、行数、保留理由与风险在独立审查记录和覆盖报告中，不能把这些列为已经抽取完成。

实测大倾角目前不会在任何飞行阶段统一触发一个独立停机门；RC 地面准入与视觉目标另有倾角限制。本轮把这点写准，没有新加停机条件。可选 CSV 仍同步 flush，异步日志的 100 ms 是名义期限而非硬实时上界。视觉字符串资源预算、协方差完整变换、真实尺度和测量时钟仍需后续合同与数据。

本轮主机证据不能证明 Orange Pi 的 ARM64 性能、真实 PX4 输出采用、动力余量或自由飞行稳定性。过去的控制超时、反馈异常和实际高度参考问题，需要同程 ULog、report、配置身份与负载记录。准备内容仍见 [下一阶段清单](../FC01_NEXT_STAGE_PREPARATION_20261111.md)，无需为当前接口另创消息包。

早期分批范围只有八个文件的记录保留在 Git 提交 `5c1555d` 及相应原始日志中；本文件与最终覆盖 JSON 合并本轮全部代理的真实复核记录，取代其“其余文件未处理”的阶段性描述。每条完成记录绑定最终文件 SHA，不依靠旧摘要或汉字计数。
