# FC01 香橙派起飞、定高、降落入口

这是现有 ARM64 R6.3.2 控制器的操作入口。当前任务是姿态与相对高度控制；水平定点、视觉导航仍需后续接入。入口保留原生 C++ 控制器及其保护逻辑，不重刷飞控、不覆盖原工程、不下载或安装依赖。

## 一次启动

将 `FC01_OrangePi_Control_20261027.sh` 复制到香橙派桌面，在香橙派本地交互终端执行：

```bash
bash ~/Desktop/FC01_OrangePi_Control_20261027.sh --flight
```

启动会自动展开文件、加载 Humble 和正确的 `install_r632` 环境，复用现有 115200 Agent，检查控制器和实时反馈。启动本身不会解锁。终端会持续显示缺少的条件与状态；不需要另外执行 topic hz 或反复粘贴检查结果。

需要起飞时，在同一个入口中输入：

```text
takeoff 1.5
```

这会依次请求 RC 接管路径、姿态控制准备、一次 1.5 m 相对高度起飞。等待进入 `HEIGHT_HOLD`；保持高度由原生状态机自动完成。高度使用起飞前地面参考 `z0-z`，不是本地坐标 z 的绝对值。当前允许 `0 < 高度 < 5 m`，默认高度 1.5 m。每个控制器进程最多提交一次 TAKEOFF，不自动重试解锁。

```text
land
```

请求原生下降、接地确认及后续退出流程，同时取消尚未提交的起飞准备。`status` 查看状态和阻塞条件；`quit` 请求降落/释放并等待原生控制器退出。Ctrl+C、断开终端和输入结束也会进入原生退出/恢复路径。飞行期间不要强制结束控制器；程序会等待恢复完成，必要时保留 Agent。

原有最长飞行时限为 30 s，入口原样保留。它不是“悬停满 30 s”的计时器。当前模式不提供水平 `hold`、`vel` 或视觉导航命令。

## 本次会话参数

`--flight` 表示操作者明确选择下面现有候选参数与 RC 接管路径。入口仅在独立会话 YAML 中开启 `flight_actions_enabled`、`arm_enabled`、`takeoff_enabled`、`flight_parameters_confirmed`、`rc_takeover_confirmed`；这不构成新的实机标定证据。`flight_enabled` 是另一个旧模式的开关，在 `attitude_altitude` 下必须始终为 false，否则原生配置校验会拒绝启动。参数原值和源 YAML 保持不变。`autonomous_failsafe_confirmed`、`bench_arm_only_enabled` 保持关闭，未补造 PX4 Land 回退证据。

| 参数 | 保留值 |
|---|---:|
| 控制频率 | 20 Hz |
| 候选悬停推力 | 0.50 |
| 起飞推力余量 / 起飞前上限 | 0.04 / 0.54 |
| 爬升 / 下降速度上限 | 0.3 / 0.2 m/s |
| 高度 / 倾角上限 | 5 m / 10° |
| 飞行时限 | 30 s |
| 落地消息超时 / 样本间隔 | 2.5 / 1.25 s |

UART入口仍为香橙派 `/dev/ttyS2 @115200`，ROS domain 0。用户最新报告的 FC01 物理对端是 **USART6/RX6-TX6**，但现场 DDS 日志显示 `/dev/ttyS3`，本地源码把它映射为 **UART4/PB8-PB9**，两类证据冲突；不改现有链路、不据此重设参数。候选香橙派 UART6 ↔ FC01 UART4/TELEM3 仍未启用且不能视为空闲，见[双串口映射审计](docs/FC01_DUAL_UART_20261105.md)。入口不更改飞控参数。原生控制器仍独立检查 RC、时钟、ACK、发布者独占、Z/Vz、倾角、估计器重置与接地证据；条件不足时拒绝动作。

## 只检查与后续启动

不带参数或使用 `--check` 时，全部动作门关闭，采集约 15 s 后自动退出并生成报告：

```bash
bash ~/Desktop/FC01_OrangePi_Control_20261027.sh --check
```

已展开后也可以直接运行：

```bash
bash ~/FC01_OrangePi_Control_20261027_R2/start.sh --flight
```

同一版本可以重复启动。R2 默认展开到独立的 `~/FC01_OrangePi_Control_20261027_R2`，保留先前入口目录。安装器校验内嵌 ZIP 的 SHA256/CRC，拒绝路径逃逸、符号链接及覆盖不同文件。它不提供发行者签名验证。`--install-only` 仅展开文件，不启动 ROS/串口/控制器。自定义展开目录用 `FC01_CONTROL_INSTALL_DIR`；原工程位置用 `FC01_PROJECT_ROOT`。默认原工程为：

```text
~/FC01_ARM64_PORT_20261020/FC01_R632_P0_ATTITUDE_AUDIT_CANDIDATE
```

如果已有控制器或未知 UART 占用者，入口会保留它并停止本次启动。单个当前用户的匹配 Agent 会被复用，退出时不会终止它。只有自建 Agent 在原生控制器正常退出、且有新鲜的 IDLE/SAFE_DISARMED 未解锁接地证据时才会被停止。

## 自动报告

每次会话保存在 `~/FC01_control_runs/<时间_编号>/`，包含会话 YAML、控制器日志、CSV、控制台收发记录、最后状态、首个拒绝/保护原因及 `report.zip`。运行中持续保存日志与轻量状态摘要；ZIP 压缩在原生控制器退出后进行，以免慢速 SD 卡上的压缩工作打断心跳。程序会显示报告完整路径；需要排查时提供这一个报告即可，无需再手动跑一组诊断命令。复用的外部 Agent 没有被本入口接管日志，报告会记录其 PID。报告仅归档指定会话文件，不收集完整环境、凭据或其他工程。单文件超过 8 MiB 时仅裁剪报告副本，原文件保留。终端输出使用有界后台队列，终端断开或停止接收输出不会阻塞控制循环。

## 已知边界与下一阶段

用户已测得：姿态/本地位置约 20 Hz，状态约 2 Hz、落地约 1 Hz；30 s 内关键样本时间戳递增、Z/Vz 有效；115200 链路有连续 480 次 Ping 回复且未增加重连。这说明通信与数据路径已通，不能代替实机悬停结果。

本包在开发机验证操作顺序、进程生命周期和离线安装；未在你的 ARM64 设备上执行，也未完成实机起飞或悬停标定。首次运行若被已有保护拒绝，报告会保留具体证据；入口不会放宽保护来强行起飞。

定高动作确认后，下一阶段使用实际视觉里程计，经坐标/时钟/质量检查接入 PX4 外部估计与导航控制。当前包没有开启这条路径，也没有伪造视觉数据或位置有效标志。
